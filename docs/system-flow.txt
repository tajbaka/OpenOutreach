================================================================================
OPENOUTREACH SYSTEM FLOW
================================================================================
Architecture snapshot: 2026-08-26 (CRM v2)

Runtime flags come from .env. Do not copy secret values into this file. Every
non-test process uses the same Postgres DATABASE_URL; there is no runtime
SQLite fallback.


================================================================================
1. LINKEDIN DAEMON  (manage.py with no arguments)
================================================================================
The long-running daemon owns browser-backed LinkedIn work. Active hours, rest
days, feature flags, and per-profile limits gate its work.

CONNECT
  - Sends a connection request/note when enabled.
  - Persists successful outbound activity to crm.Message.

SWEEP_CONNECTIONS
  - Detects accepted invitations in bulk.
  - Advances per-Lead/per-Campaign Deal automation state.
  - Captures the conversation snapshot and persists crm.Message rows.

FOLLOW_UP / GMAIL SEQUENCE
  - Outbound automation lanes remain separately feature-gated.
  - They are not invoked by CRM v2 context, publication, drafting, or connector
    workflows.

Deal is an outreach-delivery state machine. Deal.state=COMPLETED means that
automation lane finished; it never means Closed Won.


================================================================================
2. CONTEXT INGESTION  (manage.py sync_crm_v2_context)
================================================================================
crm.Message is the stored LinkedIn/Gmail communication timeline. crm.Meeting
and crm.MeetingNote store meeting facts and note context.

Apply mode:

  .venv/bin/python manage.py sync_crm_v2_context --apply

It:
  - refreshes configured Gmail human threads;
  - persists Gmail-delivered Gemini/Meet notes;
  - creates only strictly validated corporate email-first Leads from private
    discovery state and relinks their exact threads when needed; and
  - incrementally syncs/rematches Granola.

It never publishes Sheets or sends messages. Default invocation is no-write.

Separate prerequisites:
  - daemon/realtime/sweep paths capture LinkedIn events;
  - manage.py backfill_messages keeps later LinkedIn replies fresh;
  - docs/data-sync-workflow.md covers Calendar and Drive-only Gemini context.

Granola is primary meeting-note context when deterministically matched; stored
Gemini is secondary. Context alone cannot make stale work eligible.


================================================================================
3. CANONICAL SALES CRM IN POSTGRES
================================================================================
Lead / Deal remain contact and outreach-automation records.

The account-first sales domain is separate:
  Account
    -> Opportunity (owner, stage, 15-step motion, commercial state, admission)
      -> OpportunityContact (champion / decision maker / stakeholder / other)
      -> OpportunityAction (one current open/waiting Action)
      -> OpportunityStageEvent (audit history)
      -> OpportunitySheetState (three-way merge baseline)

Admission priority:
  1. human pin / Sales Motion / human-managed opportunity;
  2. real upcoming or completed meeting;
  3. human Gmail inbound/bidirectional thread;
  4. substantive bidirectional LinkedIn conversation.

One-sided outbound remains People-only. Don't send stops outreach to the exact
target but does not erase account relevance. Owner, stage, close state, and
human actions remain authoritative.


================================================================================
4. CANONICAL CRM PUBLICATION  (manage.py refresh_crm_v2)
================================================================================
Default invocation runs the exact DB reconciliation/action path under rollback
and performs zero Sheet writes:

  .venv/bin/python manage.py refresh_crm_v2 \
    --manual-pin StackArmor \
    --owner-override Ramp=Arian \
    --owner-override StackArmor=Arian

After the reviewed first cutover, scheduled publication is:

  .venv/bin/python manage.py refresh_crm_v2 --apply --routine \
    --manual-pin StackArmor \
    --owner-override Ramp=Arian \
    --owner-override StackArmor=Arian

One run:
  1. acquires the nonblocking CRM lock;
  2. opens and inventories exactly GOOGLE_SHEETS_ID;
  3. publishes the durable People prerequisite with preservation checks;
  4. reads exact People Don't send Lead IDs;
  5. resolves account evidence and reconciles DB state;
  6. imports valid human edits by stable ID;
  7. reconciles at most one current Action per opportunity;
  8. stages and verifies Active Accounts plus Actions; and
  9. swaps both live tabs atomically and commits baselines.

Routine mode requires both canonical v2 tabs and no exact legacy canonical
titles. First cutover requires a recent matching private preview_crm_v2
artifact, makes a full private workbook backup, imports legacy human state only
through exact stable IDs, and removes obsolete canonical tabs after DB commit.

refresh_crm is retired. Once either v2 tab exists it fails closed and must not
be scheduled or used as a fallback.


================================================================================
5. GOOGLE SHEETS SURFACES
================================================================================
People
  - Complete durable contact/prospecting ledger.
  - Updated in place/appended; never clear/rebuild/reorder/prune.
  - One-sided LinkedIn/outbound prospects stay here without cluttering sales.

Active Accounts
  - One row per currently relevant account/opportunity.
  - Shows owner, stage, attention, why active, last meaningful touch, who owes,
    next action, due date, and key contacts.

Actions
  - One owner-filterable current work queue plus retained handled history.
  - Requires deterministic owner, opportunity, and target contact.
  - Outreach-stopped rows expose state without a send channel/draft.

ICP Goals / separate Sales Motion workbook
  - Read-only inputs.

Retired
  - Opportunities, Pipeline, Recovery, and <Owner> - Followups are not routine
    data sources or production views.


================================================================================
6. MANUAL DRAFTING
================================================================================
manage.py generate_followups
  - Exports explicitly owned current Actions for draft generation.
  - Validates decisions by Action/Opportunity/Lead IDs plus context fingerprint.
  - Stores and republishes drafts through routine CRM v2; never sends.
  - --refresh-crm refreshes v2 context then runs routine v2 publication.
  - The retired name-based rebuild requires explicit --legacy and is never a
    scheduled production path.

Operators filter Actions by owner, review the exact conversation, send
manually, then record handled/disposition/waiting state in the stable-ID row.


================================================================================
7. WINDOWS SCHEDULED RUNNER
================================================================================
The existing Task Scheduler action still targets:

  scripts\run_sync_sheets.ps1

The wrapper runs, in order:

  .venv\Scripts\python.exe manage.py sync_crm_v2_context --apply
  .venv\Scripts\python.exe manage.py refresh_crm_v2 --apply --routine \
    --manual-pin StackArmor \
    --owner-override Ramp=Arian \
    --owner-override StackArmor=Arian

and logs run/phase markers to:

  data\logs\crm_v2_task.log

notify_sync_sheets_health retains the deployed task name but considers only the
newest run and requires both phases to finish successfully.


================================================================================
8. ONE-OFF CONNECTION IMPORT
================================================================================
  .venv/bin/python manage.py import_connections --csv <file> [--campaign N]

The command uses BACKFILL_LINKEDIN_USERNAME/PASSWORD, imports only matched
accepted connections, persists message history, and never writes Sheets
directly. The next context/publication cycle appends eligible contacts to
People and evaluates account admission conservatively.
